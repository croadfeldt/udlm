**A printer is a device that runs firmware, and gets its class.** Maintainer ask 2026-11-19: the estate's printer joins the network gear records, so its firmware can be judged against advisories like any other device's. No class fit. A new Base class, `Printer` 0.1.0: identity (maker, model, serial, and the UUID the printer states for itself, which stays the same whichever interface it is using), `management_address` and `firmware_version` outputs, and `located_in`. It adopts IPP (RFC 8011, PWG 5100.13), which is how a printer describes itself. Queues, jobs, trays and scan destinations stay with the provider. The `affected` walk's `devices` step lists it (walks.yaml 0.4.0), so an advisory reaches a printer through its firmware release, by the maker, model and version it states (rows 177, 178). Not in 0.1.0: the printer's network interfaces.
