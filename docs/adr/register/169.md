**A machine states which SSH keys its local accounts accept.** Machine 2.8.0 adds `authorized_keys`. Each entry is a local account (`login`) and one key: the public key itself (`public_key`) or a reference to a CredentialRef (`credential_ref`), never both. CredentialRef 0.9.0 adds an optional `public_key`, the public half of an `ssh_key`, so one key used on many machines is one record referenced from each. A reference entry is an `authorized_key` edge. An entry with no key asks the provisioner to issue the pair, and the realized record states the public half. How the private half then reaches the caller is not yet specified, so for now the caller generates the pair and states the `public_key`. The private half never enters a record. credentials.md no longer fixes when a credential is issued relative to its machine. A directory user's keys stay on its Identity..
