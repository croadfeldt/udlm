**A machine states which SSH keys its local accounts accept.** Machine 2.9.0 adds `authorized_keys`. Each entry is exactly one key: the public key itself (`public_key`) or a reference to a CredentialRef (`credential_ref`). The local account (`login`) is optional. Without it the key goes to the image's default account, and the realized record states the login used. CredentialRef 0.9.0 adds an optional `public_key`, the public half of an `ssh_key`, so one key used on many machines is one record referenced from each. A reference entry is an `authorized_key` edge. An entry with no key is refused: the caller generates the pair and states the public half, so no private half moves or enters a record. A provider declares which entry shapes it accepts. credentials.md no longer fixes when a credential is issued relative to its machine. A directory user's keys stay on its Identity. Maintainer rulings 2026-11-12 and 2026-11-16.
