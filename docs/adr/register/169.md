**A machine states which SSH keys its local accounts accept.** Machine 2.7.0 adds `authorized_keys`. Each entry is a local account (`login`) and one key: the public key itself (`public_key`, one OpenSSH authorized_keys line) or a reference to a CredentialRef (`credential_ref`), never both. An entry with no key asks for an account, and the realized record states the key it received. CredentialRef 0.9.0 adds an optional `public_key`, the public half of an `ssh_key`, so one key used on many machines is one record referenced from each. A reference entry is an `authorized_key` edge. The private half stays under the custody rules in credentials.md. Whether a key is supplied or generated, and when, is the implementation's choice; the credentials.md worked example no longer fixes that order. A directory user's keys stay on its Identity. Every existing record keeps its meaning. Maintainer rulings 2026-11-12.
