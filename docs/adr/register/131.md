**The merge result is checked, and a red main is announced** (WP7, #424). Two branches green on their own made main red together once, because CI judged each against the main it branched from. `validate.yml` now also runs on `merge_group`, so a merge queue checks the prospective merge result, and when it fails on main after a merge, a `main-is-red` job opens an issue naming the commit. What closes the hole is a repository setting: require `validate-registry`, with branches up to date before merging; the maintainer applies it (the PR carries the command).
