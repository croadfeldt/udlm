**The firmware record is named `FirmwareRelease`** (maintainer ruling 2026-11-19). Row 177 named it `FirmwareImage`, beside `SoftwareImage`. An image is the binary: the standards that say "firmware image" mean the file (RFC 9019, the UEFI firmware management protocol), and `SoftwareImage` is identified by its digest. This record holds no digest and is one per device model, even where one file serves several models. A release is what the firmware update standards call a version of firmware for one kind of device, with the file as an artifact beneath it (LVFS metainfo, Redfish `ReleaseDate`). `FirmwareBuild` was the other candidate; a build is the process that produces an artifact (SLSA). Renamed in one change: the class (`FirmwareRelease` 0.2.0, the same uuid), the key scheme (`firmware_release`), the walk step (`firmware_releases`, walks.yaml 0.3.0) and the `describes` target (`SoftwareBillOfMaterials` 0.3.0). Nothing changes in what is recorded or how a device is matched.
