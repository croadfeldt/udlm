**The Discovered record is the observed state, and a value's place says what it is** (maintainer ruling 2026-11-23; four-states.md, data-model-core.md). Observed and discovered are one thing: what exists now, as a provider sees it. That is the role of Kubernetes `status`, and only a provider writes it; a discovery source is a provider. A record's state says when and from whose view: Intent and Requested hold what should be, Realized what the provider built, and Discovered what is there now. Realized is a receipt that can go stale. A class's part says what can be asked for: an element is a value a requester can set, an output a value only a provider supplies. Both appear in a Discovered record as observed. A value keeps one name everywhere; no `observed_` or `current_` prefix. Knowledge classes have no desired state, so their facts are exempt.
