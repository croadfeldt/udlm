**The edge-type registry says how a walk reads each edge** (edge-types.yaml 1.1.0, service-dependencies §6.4, DEP-009, DEP-010, #TBD). Entity-relationships §3 ruled that ordering and traversal consume only `edge_type` and `strength`, but which edge types a walk follows was never written down; the ansible estate filter and the estate explorer each carried their own table. Each edge type now carries `walk`: `needs` (what must exist for A: hard `depends_on`, `contained_by`, `binds_to`), `dependents` (what B's absence reaches: hard `depends_on`, `binds_to`; containment propagates down through `cascades`, never up), `terminates` (`references`: pointing at is not needing). `soft` is never followed. A needs walk orders foundations first, a dependents walk leaves first, a cycle is DEP-002 and gets no step. A resource's location is the nearest `Location` over `contained_by`, derived, never stored (DEP-010). Consumers cite the registry and read it (DEP-009). Maintainer ruling 2026-11-09.
