**The register is one file per ruling, and the table is rendered from them.** Every ruling added one line at the same place in `docs/adr/README.md`, so any two open pull requests conflicted there. A ruling is now a file, `docs/adr/register/<number>.md`: a front-matter block and one line, the row. `registry/tools/render_register.py` renders the README's table from the files, newest on top. Its `--check` gate holds three rules: a file is named by its id and has one body line; ids are unique; the README holds no row without a file, and none that differs from its file. Rows that are files but not yet rendered pass on a branch and fail on main, so the table is refreshed in a small pull request after each merge round. The one conflict left is two rulings claiming one number, the right signal. Maintainer ruling 2026-11-04.
