**A named walk says what an advisory reaches** (walks.yaml 0.1.0, service-dependencies §6.5, DEP-019, DEP-020, #TBD). Row 167 ruled how the two ordering walks read each edge type, and both stop at `references`. An advisory reaches a running thing only through references: a package, the bill of materials that lists it, the image that document describes, the container that runs the image. Knowledge-family §4.6 described that path and no rule stated it, so each consumer would have carried its own table. `registry/walks.yaml` now holds named walks. The first, `affected`, has six steps, each a declared relationship, a reference held in a field or a derived join, and a gate proves every step against the classes. An answer keeps the affected set apart from its reach, and lists what it could not judge and the currency of what it read. The ordering walks are unchanged. Maintainer ruling 2026-11-18.
