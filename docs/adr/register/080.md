**A provider may originate a request across a provider boundary.** A VM provider whose pool is full may request raw storage from the storage provider as a request of its own. That request lives in the provider's tenant, under its authority, with its own root. It names the consumer's request that caused it as provenance only, never authority (`caused_by_request`, `DEP-018`, `PRV-012`). The fulfilling provider receives only the execution slice and placement requirements, never the consumer's tenant, entity, request or reason. Constraints arrive as placement requirements re-evaluated under current policy. The runtime link is `blocked_on` (DEP-017). Growing what a provider already owns is mechanism, not a record. This overrules the no-path sentence in the third draft of row 078. Maintainer ruling 2026-09-28, relayed.
