**A cluster carries no node pools; a pool is a record; a cluster with pools is a composition.** `KubernetesCluster` loses its inline `node_pools` element (MAJOR, 2.0.0). Every pool, including the first, is a `KubernetesNodePool` record contained by the cluster, ordered, scaled and retired on its own; the per-node sizing the inline list carried moves to the pool record as `node_resources`, the shared ComputeResources shape (1.1.0). A cluster record may have zero worker pools. Ordering a cluster with its pools as one item uses the existing composition mechanism (`constituents[]`), when needed. This is how EKS, HyperShift (`HostedCluster` + `NodePool`) and Cluster API (`Cluster` + `MachineDeployment`) model it | Ruled — row-only (maintainer decision 2026-09-12); applied: `registry/classes/resource/kubernetes-cluster/_base.yaml`, `registry/classes/resource/kubernetes-node-pool/_base.yaml`, `use-cases/compute/006-provision-compute-cluster.yaml`
