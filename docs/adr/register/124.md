**A machine mounts network shares; a volume binds to a machine one way** (#680, slice 2: file claims). Machine 2.5.0 gains `mounts`: each a FileShare (`source_ref`), one of its exports (`share`), a `mount_path` and `read_only`, with a `mounts` edge the machine declares. It is the file counterpart of `disks`: a disk is attached by the hypervisor and realized by a Volume; a share is mounted by the guest from a FileShare, the shared (read-write-many) case row 112's split gives to FileShare. The names are UDLM's Container `mounts` and Kubernetes `volumeMounts`. Volume 0.17.0 drops `attaches_to`: for a machine's disk it restated `realizes_disk`, and shared multi-attach block storage has no use case yet (when one appears, `realizes_disk` widens, bounded by `access_mode`). KubeVirt-style `filesystems` (a host directory shared into the guest by the hypervisor) waits for a use case too: no field without a reader (row 108).
