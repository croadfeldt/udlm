**A policy holds logic, and a policy configuration holds the values one deployment gives it** (maintainer ruling 2026-11-20). One `policy` record held both, and a profile entry's `settings` was a third place a value could sit. Two deployments that wanted one rule with different values kept two copies of the rule. The `policy` record now holds the facts it reads, the rule, a `parameter_schema` and its output. A new `policy_configuration` record holds the parameters, tenant, domain, lifecycle scope, enforcement level, schedule clauses, audit and notification settings. A configuration `configures` exactly one policy, pinned to a version, so new logic reaches a deployment only when its own record moves the pin. Its parameters satisfy that policy's schema. A profile turns a configuration on or off and holds no values for it. A `proposed` policy is provisional logic and runs in shadow mode only (POL-011 to POL-015).
