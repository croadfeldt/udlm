**UDLM ships the profile mechanism, not the postures** (lockdown WP5; #488, #489, #490). The profile record shape, its `contains` list and activation are UDLM's and stay. The six named postures — homelab, dev, standard, prod, fsi, sovereign — are governance choices, so their records leave this repo for the UDLM Profile Set (croadfeldt/udlm-profiles); one worked example of the mechanism remains, in the example namespace. A profile-governed setting is defined once, in its owning document, and the index lists them; what a posture requires of it is the Profile Set's. The last per-posture value table (callback-token lifetime) and the two picked numbers — request groups capped at 50, auto-approve score capped at 50 — go the same way: a profile sets them, UDLM sets none. Maintainer ruling 2026-08-10, applied 2026-11-03.
