**Adoption is a lifecycle operation, `adoption`: the act of bringing an observed resource under management** (maintainer ruling 2026-11-23; policy-contract §2.2). DCM ADR-017 defines the steps: reverse placement, a provider's claim (Discovered to Realized, same UUID), then an intent backport. UDLM ADR-030 defines the loop: run the candidate intent dry, approve it, converge. No operation type named the act, so no policy could scope to it. Records already state the facts (`origin`, `provider`, `matched_by`, `correlation_ids`, per-source `authority_level`); during adoption, a policy decides whether an observation counts, who owns it and which provider claims it. `adoption` joins policy.schema.json, the `operation.type` fact, the test framework and the default scopes of structural validation and transformation, which ADR-030's dry run needs. A policy that reacts, such as ITSM Action or Orchestration Flow, covers adoption only when its author lists it; an ITSM record on adoption comes from a policy someone authors.
