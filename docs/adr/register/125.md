**Object storage is a Bucket a machine uses with a credential** (#680, slice 3: object claims). Two new Bases adopt Kubernetes' Container Object Storage Interface (COSI). BucketClass 0.1.0 (`driver_name`, `deletion_policy` Delete \| Retain, `parameters`) is the object counterpart of StorageClass. Bucket 0.1.0 carries `bucket_class`, `protocols` S3 \| Azure \| GCP and an optional `deletion_policy` override; outputs `bucket_id` and `endpoint`; `provisioned_by` a StorageCluster. COSI value sets are copied verbatim (row 111). Machine 2.6.0 gains `buckets`: each a Bucket (`source_ref`), its CredentialRef (`credential_ref`, COSI's BucketAccess held by reference, CPX-001), and `read_only`. Like a share and unlike a disk, a bucket is shared, so the machine references one rather than claiming its own. With rows 122–124 a Machine now claims block (`disks`), file (`mounts`) and object (`buckets`) storage, each satisfied by a class adopting the matching Kubernetes standard. COSI is alpha upstream; its names are adopted, not its API.
