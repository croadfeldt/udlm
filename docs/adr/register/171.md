**A class that moves carries every class beneath it, and a provider's bound version is its statement of support** (amends ADR-045 Decisions 1, 3 and 8; VERSIONING.md). A subclass's served spec is compiled from its ancestors, so a Base change altered what `Machine.VM 2.4.2` meant without changing the number. When a class's version moves, every class beneath it now advances by at least the same level. `scripts/regen.sh` writes the bumps and moves the examples that pinned the old versions. Each subclass version therefore names exactly one Base version. A class inside the registry still may not pin its Base, so siblings share one Base and records stay portable between them. A provider registers a class at a version, and that version says it honours every element there. The compat gate now checks the served specs; it had watched a retired directory. No class was re-versioned to catch up. Maintainer ruling 2026-11-17.
